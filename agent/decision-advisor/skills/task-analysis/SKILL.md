# 谋事研判工作流（三阶段）

## 何时使用

用户描述一件想做的事（开店、装修、办活动、上项目、组织出行等），想知道「会遇到什么问题、怎么准备、自己该盯哪块」时，调用本技能。

## 标准流程

1. **澄清事项**：目标、范围、时间、预算上限、团队与干系人、是否涉及设备 / 施工 / 场地 / 出行 / 第三方。
2. **检索经验库**：用 `mcp__obsidian__*` 检索同类事项复盘（先 tags / topic，再全文补充）。
3. **三阶段研判**：按下方清单逐项分析，每项落到「问题 → 判断 → 依据 → 建议」。
4. **审查**：涉及设备、电路、施工的项目追加「审查维度」。
5. **成稿**：按输出模板产出报告。

## 前期准备清单（15 项）

| # | 事项 | 研判要点 |
| --- | --- | --- |
| 1 | 有无相关经验 | 用户与团队有无同类经验；经验库同类复盘结论；无经验时补课路径（找有经验的人 / 缩小试点 / 聘请顾问） |
| 2 | 将要面对的风险责任 | 法律 / 安全 / 资金 / 违约责任各由谁承担；哪些可转移（合同、保险、外包），哪些必须自留 |
| 3 | 细致的时间安排 | 倒排工期；关键路径、依赖与审批；缓冲时间；哪个环节延误会连锁 |
| 4 | 预算安排 | 显性与隐性成本；应急金比例；付款节点与尾款杠杆；经验库同类事项实际超支幅度 |
| 5 | 人员安排与协调团队 | 谁决策 / 执行 / 验收；分工书面化；协调机制（例会、群、单点对接人） |
| 6 | 方案计划确定 | 方案是否评审过；有无备选方案；变更流程是否约定 |
| 7 | 如何高质量交付 | 验收标准可量化；交付物清单；样品先行、分阶段验收 |
| 8 | 怎样规避风险 | 风险清单（概率 × 损失）；规避措施与触发条件；最坏情况的退出方案 |
| 9 | 进度同步 | 同步频率与形式；谁负责汇总；延误如何上报与决策 |
| 10 | 如何结合 AI 排查问题 | 方案评审、合同审查、清单核对、风险扫描交给 AI；AI 输出必须人工复核的边界 |
| 11 | 整体流程是否想通 | 从头到尾走一遍，找逻辑断点与未定义事项（谁、何时、用什么、交付给谁） |
| 12 | 自己的工作主体放在哪块 | 列出「只有用户能做」的事（关键决策、关键关系、最终验收）；其余授权或外包 |
| 13 | 场地是否有问题 | 产权与合规、消防与物业审批、承载能力、水电条件、租约条款 |
| 14 | 出行是否有问题 | 人员与物料交通方案、时间成本、天气与节假日影响、备选路线 |
| 15 | 第三方插手怎么协调 | 第三方介入点、诉求与话语权；接口人单一化；一切承诺书面确认 |

## 中期实施清单（4 项）

| 事项 | 研判要点 |
| --- | --- |
| 物料筹备 | 清单先行、到货验收、备选供应商、库存与损耗 |
| 设备准备 | 设备清单与调试、租赁 vs 购买、到场时间、备用设备 |
| 场地安全 | 消防通道、用电负荷、防护措施、安全责任人 |
| 人员安全 | 保险、安全交底、应急预案、极端天气与突发疾病处置 |

## 后期收尾清单

- 验收与结算：按交付物清单逐项验收，尾款验收后支付
- 场地与设备恢复：退场清场、设备归还、押金退回
- 责任了结：合同终止确认、保修条款留存、保险处理
- 复盘沉淀：写成经验笔记存入 Obsidian（frontmatter：topic / tags / 阶段 / 审查 / 结果 / date）
- 关系维护：感谢协作方，留存联系方式与合作评价

## 审查维度（涉设备 / 电路 / 施工必查）

| 维度 | 检查点 |
| --- | --- |
| 设备风险 | 故障率与停机影响；备用设备；操作人员资质 |
| 电路风险 | 用电负荷与线路承载；接地与漏电保护；电工验收 |
| 施工风险 | 高空 / 动火 / 动水作业资质与防护；施工区域隔离；保险覆盖 |
| 设备替代 | 关键设备替代方案；替代品性能差距与成本差 |
| 耐久性 | 材料工艺在项目周期内是否够用；临时措施能否撑到结束 |
| 耐用性 | 重复使用损耗速度；维护成本与周期 |
| 性价比 | 租 / 买 / 借对比；低频需求是否值得购置；二手与租赁渠道 |

## 输出模板

```
【事项概述】一句话复述要做的事
【总体判断】可行 / 有条件可行 / 不建议 + 一句话理由

【前期准备研判】（15 项逐条）
▸ 有无相关经验
  - 面临的问题：…
  - 具体判断：…
  - 经验依据：<笔记标题>（无则标「推断」）
  - 建议：…（标注：用户需亲自投入的时间 / 责任归属）
▸ …（其余各项）

【中期实施研判】（4 项逐条）
▸ 物料筹备 …

【后期收尾清单】（按项目定制）

【审查意见】（涉设备 / 电路 / 施工时）
- 电路风险：…

【用户工作主体定位】只有用户能做的事：…
【责任转移方案】合同 / 保险 / 外包 / 书面确认：…
【经验引用】<引用的笔记列表>
【无先例部分】<需用户补充信息的点>
```

## 检索要点

- 经验笔记 frontmatter 带 `topic`、`tags`、`阶段`、`审查`、`结果`，按字段检索最准。
- 同一主题多篇冲突时，优先时间更近、结果更差的一篇（教训比成功更有信息量）。
- 无同类事项时明确写「无先例」，只给标注「推断」的一般性判断。

## 原则

- 时间与责任是两把尺子：每条建议自问——占用用户多少时间？让用户多背多少责任？
- 具体优先：判断落到环节、数字或机制。
- 敢于否定：大概率失败就直说，并给补救条件。
- 区分事实与推断。
- 服务于行动：每条分析落到「建议怎么做」。
