# D23.25 · 大儒呈作：根治书中残句（半句悬尾 +「6 节定稿未竟」）

用户反馈：生成的书里仍有多处残缺——句子写了一半就断（「这当然」
「我有时候半夜醒过来」「那之前」「忽然想起动笔那天的」），
卷尾且有「（其中 6 节定稿未竟，沿用初稿）」。要求任何一节都不得以
半句收尾，管线中断要能无缝续写。

## 一、根因（五层叠加）

1. **Worker 末轮照发 done**：runLoop 到 maxRounds 时，即使末句悬在
   半空也照常发 `done`，残句就此定稿。
2. **前端无视 short/dirty**：done 里的短幅、脏尾标记客户端根本不看，
   拿到就组装成书。
3. **分章定稿报文膨胀**：finalizeByChapter 把此前所有已定稿章节随文
   发送，越靠后报文越大，连续超时 → 6 节回退初稿。
4. **验收只比对初稿**：定稿只跟初稿比长度、从不跟配额比，长短标准
   错乱。
5. **配额下限的暗坑**：Worker `sanitizeSection` 配额下限 500，把前端
   给自序/后记/小章的 200–400 配额整体抬高，初稿系统性超标，好的
   定稿（如 4012 字）反被误判缩水而触发「定稿未竟」。

## 二、修复（纵深防御，两端各守一遍）

### Worker `worker/src/book.js`（须 wrangler deploy）

- 配额下限 500 → **150**，尊重前端小章配额。
- runLoop 末轮不再草率收笔：新增 verdict 判定，末轮仍悬半句或篇幅
  未足则转入**收束救援 runRescue**——两次小额请求：
  - 脏尾：只取末尾 500 字，请大儒「200 字以内把悬着的句子说完」
    （maxTokens 600，60s 超时），便宜可靠；
  - 干净但短：正常承接续写一轮。
- done 显式携带 `short / dirty / sentinel`，不再让客户端猜。
- 新增 `endsCleanAt`：以 `。！？…」』）”` 收尾才算干净。

### 前端 `scripts/book.js`（push main 即上线）

- 起草 **3 次尝试**：不净或不足配额 85% 则带 live seed 续写重试；
  最终仍不净则 `trimDangling` 截到最后一个句读——**残句永远进不了
  成书**；确实未足配额的记入 `state.shortfalls`。
- 全书定稿（≤12000）验收改为 **目标字数 95% + 不低于初稿 80% +
  干净收尾**；失败重试一次，再败才回退初稿并诚实标注。
- 分章定稿（>12000）：(a) 上下文只带**最近 2 节**已定稿，报文不再
  滚雪球；(b) 验收按配额 95% / 初稿 80% / 干净收尾，重试一次；
  (c) 回退初稿用 trimDangling 兜底，并记录章节名。
- 卷尾注区分两类：「N 节定稿未竟，沿用初稿」与「N 节起草未足配额」。
