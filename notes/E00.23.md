# E00.23 · 反馈①：线上真书「8 节定稿未竟、3 节起草未足」——心跳治误杀

用户按 D23.25 修复后再呈真书：残句没了，但卷尾标「8 节定稿未竟，
沿用初稿；3 节起草未足配额」，全书 18989 字未足目标。大半节没过
定稿，必须查。

## 一、线上复现（真实页面打生产 Worker，20000 字）

fetch 包装逐请求计时（t0 取响应头到达时）：

| 阶段 | 首字静默 |
|---|---|
| 起草 1–3 节 | 0–1s |
| 起草 6–9 节 | **17–43s** |
| 后记（单节内部 4 轮＋救援） | 整节耗时 **458s** |
| 定稿 1–5 节 | 2–11s |
| 定稿 6–9 节 | **25–49s**（第 7 节 49s，已越 45s 看门狗，侥幸通过） |

结果：**20306 字，已成卷，10 节定稿零回退，各节干净收尾**。

## 二、判定

非逻辑 bug，是**火山方舟端点高峰时 prefill 长静默**：

- 客户端 openBookSSE 看门狗：45s 收不到事件即 abort；慢窗里两次
  重试都被误杀 → 回退初稿；起草同理 → 未足配额。
- 用户那次撞上持续慢窗（8/8 节两次重试均失败），复现这次端点
  稍缓（最长 49s 擦线），故零回退。

## 三、修复

### Worker `worker/src/book.js`（须 deploy）

- runLoop 每轮、runRescue 每次：等待上游期间 **12s 发一个
  `{t:'ping'}` 心跳**，结束即清 interval。
- 效果：客户端 45s 看门狗与 CF 边缘空闲计时都不再把慢等当死流；
  上游真超时（110s）Worker 仍发 error，重试语义不变。

### 前端 `scripts/book.js`（push 即上线）

- 逐节定稿重试 2 次 → **3 次**（settle 与 catch 的 `attempt<1`
  改为 `attempt<2`），慢窗中多一次机会。

## 四、验证
