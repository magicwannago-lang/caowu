# G09.44 · 反馈③：诊断坐实「定稿缩水／末句未收×6」——对齐验收口径

F09.35 的卷尾诊断在真书上见效：6 节失败全部是**验收不过**（非限流、
非超时），另有 3 节起草未足配额。全书 14402 字未足目标。

## 一、病根

1. 定稿尺子比起草还严：起草 0.85 配额即放行，定稿要 0.95。起草只
   写到 0.85–0.94 的节，定稿一字不减也必败，三试注定全回退。
2. 末句未收连累整节：末字不在句读表即整节拒绝，未先尝试截悬尾。
3. 句读表只认中文标点，ASCII `. ! ?` 收尾被误判悬尾。

## 二、修改

### 前端 `scripts/book.js`（push 即上线）

- finalizeByChapter 的 settle：先 `trimDangling` 截悬尾再验收；
  末句未收不再单独致退；
- 长度口径：起草已足 0.85 配额的节，定稿守「≥0.85 配额且 ≥初稿
  0.9」；起草本就未足的 shortfall 节，只要求「≥初稿 0.98」不缩水；
- `TAIL_PUNCT` 与 trimDangling 句读表补 ASCII `. ! ?`。

### Worker `worker/src/book.js`（**须 deploy**）

- 三处句读字符集（atPause、截尾 match、TAIL_PUNCT_RE）统一补
  ASCII `. ! ?`。

## 三、验证

- node --check 两文件通过；
- regex 行为实测：中文句读/ASCII 句判干净、悬尾判否；截尾截到
  最后一个句读，ASCII 句号不误剥。
