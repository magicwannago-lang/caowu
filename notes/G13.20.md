### 陈位规则：从两档扩到三档，并且不再裁画

上午那一轮真正花心思的地方。旧逻辑只认 `wide` / `tall` 两档，
其余一律塞 4:3 铺满。新图里冒出一张 **1:1 的方构图**（`05-静瓶朱枝`），
方到 4:3 里会被左右各削一刀，而这张的瓷瓶正贴着右缘 —— 削掉的正好是瓶。

改了三处：

1. **`gen-manifest.py`**：陈位判定抽成 `slot`，秩序是
   **`_meta.json` 点名 > 宽高比兜底**。点名 `wide`/`tall`/`scale` 就照点名来；
   没点名时按比例归位 —— `>2.0` 判 `wide`，`<0.85` 判 `tall`，
   `<=1.15` 判 `scale`（近方构图），中间那段（1.15–2.0 的常见横构图）不另给陈位，
   走默认 4:3。
2. **`manifest.json` 带上了真实宽高比 `ratio`**（六位小数）。
   这是这次最要紧的一条 —— 见下。
3. **`player.js` + `components.css`**：`scale` 一路带到 `figure`，
   给 `.relic-scale .relic-media { aspect-ratio: 1/1 }`；
   并且**用 `ratio` 覆盖 CSS 的默认比**——

   ```js
   if (im.ratio) media.style.aspectRatio = String(im.ratio);
   ```

   有了这一句，「点名点错了」只会换个排法，**不会真把画面裁掉**。
   CSS 那几档从此是默认值，真实比例说了算。

另外两处排版上的补丁：

- `#gallery { align-items: start }` —— 默认 `stretch` 会把同一行的卡片拉成一样高，
  方幅旁边多出一段空白，题款悬在空处像没写完。改成各依内容收住。
- `_slot_agrees()` 只提醒不报错：点名 `wide` 却只有 3:2 之类，
  终端说一句「已按实际比例排，未裁」，不拦着。

顺带一条**名不副实**：`01-远山` 是 3:2（1.4995），
但 `player.js` 里有「第一幅默认给横长陈位」（`im.wide || i === 0`），
所以它仍占满一行。**靠 `ratio` 兜住了，画面按 3:2 显示，裁切发生在宽高比层面，
不是 `cover` 层面** —— 想成窄长横幅的话得另说，见第四节。
