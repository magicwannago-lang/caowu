## 一、部署：卡在域名证书，等 DNS 修

站点本体没问题，HTTPS 起不来。

| 项 | 状态 |
|---|---|

| CNAME | `sevencolor.space` 已挂（仓库 CNAME 文件 + Pages 设置） |

| HTTPS | **不可用**，返回 GitHub 兜底证书 `CN=*.github.io` |

GitHub 接口的原话：`PUT /pages` → `The certificate does not exist yet`。

### 卡点在阿里云 DNS（NS: `vip1/vip2.alidns.com`），两处要改

```
sevencolor.space      A  185.199.108.153   ← GitHub ✅
sevencolor.space      A  185.199.109.153   ← GitHub ✅
sevencolor.space      A  185.199.110.153   ← GitHub ✅
sevencolor.space      A  185.199.111.153   ← GitHub ✅
sevencolor.space      A  47.116.59.43      ← ❌ 阿里云上海，80/443 全不通，删
www.sevencolor.space  A  47.116.59.43      ← ❌ 同一死 IP，删或改 CNAME → magicwannago-lang.github.io
```

另需确认 TXT `_github-pages-challenge-magicwannago-lang.sevencolor.space` 是否存在
（域名所有权验证；本机解析不出外网 DoH，看不到）。

### DNS 改完后的收尾步骤

1. 验证 `getent hosts sevencolor.space` 只剩 4 个 GitHub IP
2. 盯证书签发（`openssl s_client -connect sevencolor.space:443 -servername sevencolor.space`）
3. `gh api -X PUT repos/magicwannago-lang/caowu/pages -f https_enforced=true`
4. 复验 https + http 跳转

**权限边界**：本机只有 GitHub 凭据（`gh` 已登录 `magicwannago-lang`），
**没有阿里云 DNS 的 access key**，DNS 那两步做不了，需要用户在控制台改或给凭据。
